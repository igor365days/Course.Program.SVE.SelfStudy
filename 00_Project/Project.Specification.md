# Project Specification — Course.Program.SVE.SelfStudy

## 1. Назначение

Создать самостоятельный долгосрочный курс шведского языка на основе книги Е. Л. Жильцова **«Шведский язык. Самоучитель» (2-е изд., 2014)** и накопленного методического опыта проекта `Course.Program.SVE`.

Курс должен организовывать последовательное обучение, практику и контроль фактического освоения материала.

## 2. Главная цель

Организовать действия учащегося для внимательного, последовательного и полного обучения с контролем процесса и результатов, чтобы получить максимально возможный результат обучения.

Скорость прохождения не является главной целью. Приоритет имеют качество, полнота и устойчивость освоения.

## 3. Два слоя системы

### Канонический курс — GitHub

GitHub хранит программу, структуру, последовательность, Unit, разделы, контрольные точки, учебные планы, методику, ресурсы и версии курса.

### Практическое прохождение — ChatGPT Project

Project организует фактическое прохождение конкретным учащимся: текущее состояние, результаты проверок, ошибки, повторение, текущую учебную задачу и следующий шаг.

Принцип:

`GitHub = что и в какой последовательности изучать.`

`ChatGPT Project = как конкретный учащийся проходит курс.`

## 4. Каноническая архитектура маршрута

Курс содержит **18 исходных уроков, 56 Unit и 5 разделов с 5 контрольными точками**.

Каждая Unit относится ровно к одному разделу. Unit внутри раздела проходят последовательно. После последней Unit раздела проводится его CP. Успешный CP открывает следующий раздел.

```text
Section 1 → Units → CP-1
Section 2 → Units → CP-2
Section 3 → Units → CP-3
Section 4 → Units → CP-4
Section 5 → Units → CP-5
```

Unit не объединяются, не разделяются и не перестраиваются ради удобства ChatGPT Project.

## 5. Исходный материал

Книга является основным источником содержания. Содержание книги и методические решения курса должны оставаться различимыми. Внешние материалы обозначаются отдельно.

## 6. Методическая модель

Базовый цикл:

`Введение → Разбор → Управляемая практика → Самостоятельное/коммуникативное применение → Проверка → Фиксация результата.`

Цикл адаптируется к конкретной Unit.

## 7. Контроль освоения

Завершение определяется достижением заявленного результата, а не чтением материала.

При необходимости проверяются понимание, воспроизведение, самостоятельное применение, коммуникативное действие, точность и устойчивость результата.

CP является интеграционной проверкой всего раздела и обязательной границей перехода.

## 8. Архитектура учебных чатов

Unit является учебным объектом, но не обязательно отдельным чатом.

Основная модель Project — один непрерывный **Learning Session**, в котором последовательно проходят несколько Unit. Новый Learning Session создаётся только при необходимости из-за размера/контекста чата или другой операционной причины.

Отдельный чат для каждой Unit не является требованием курса.

`COURSE ORCHESTRATOR` является отдельной управляющей сессией и не заменяет Learning Session.

## 9. Организация обучения

Система должна обеспечивать последовательность, практику, выявление ошибок и пробелов, целевое повторение, контрольные точки, фиксацию результата и определение следующего шага.

Учащийся не должен самостоятельно реконструировать маршрут курса или заниматься его администрированием.

## 10. Автономность

Курс должен поддерживать работу блоками без постоянного подключения к интернету. Для критически важных внешних ресурсов по возможности предусматривается автономная альтернатива.

## 11. Версионирование

Изменение канонического содержания или маршрута фиксируется в GitHub и при необходимости получает новую версию курса.

Изменение состояния обучения учащегося не изменяет версию канонического курса.

## 12. Pre-launch

Проект пока не используется для реального обучения. Архитектуру, структуру файлов, разделы, Unit и инструкции можно свободно перерабатывать до начала реального прохождения.
